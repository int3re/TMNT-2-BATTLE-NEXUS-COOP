Подробные адреса и доказательства лежат в [re/notes.md](../re/notes.md).

## 0. Коротко

**Почему игра не запускается.** «Unkown Error» (так, с опечаткой, в самой игре) — это не DRM и не
DirectX. Это ошибка в самой игре: при старте она сохраняет настройки **6** геймпадов, а массив
выделяет только на `1 + число подключённых джойстиков` (клавиатура + джойстики). Без геймпадов функция читает за концом
буфера. На старых Windows за буфером была «чужая» память, и всё проходило. На Windows 10 буфер
оказался в конце страницы кучи, отсюда нарушение доступа. `catch(...)` в WinMain превращает его
в «Unkown Error». Исправление — одна функция в памяти, exe на диске не меняется.

**Что предлагаю сделать (по этапам):**

| Этап | Что получите | Размер |
|---|---|---|
| **0. Запуск и экран** (сделан, tmnt2net 0.1.0) | игра стартует; любые разрешения; полный экран / без рамки / в окне; Alt+Enter; картинка без растяжения; лог ошибок | S |
| **1. Широкий экран** (сделан, tmnt2net 0.2.0) | Hor+ (шире обзор, не растянуто), HUD и меню в центре 4:3, ролики с полями, vsync / ограничение кадров | M |
| **2. Управление** (сделан, tmnt2net 0.3.0) | геймпады Xbox/PS (XInput/DirectInput), переназначение, «кто чем управляет» для 1–4 игроков | M |
| **3. Подготовка к сети** (сделан, tmnt2net 0.4.0) | детерминизм: главный тик, ввод, RNG, барьеры загрузок; повтор записи ввода без расхождений | L |
| **4. Сетевая игра** (сделан, tmnt2net 0.5.0) | **до 4 игроков**, у каждого своя копия игры (lockstep, без стрима видео); Steam / LAN / IP / код | L |
| **5. Меню в стиле игры** (сделан, tmnt2net 0.6.0) | «СЕТЕВАЯ ИГРА» и «ДОПОЛНИТЕЛЬНО» в главном меню, буквы игры | M |
| **6. Установщик** (сделан, tmnt2net 0.7.0) | один setup.exe: найти игру, проверить exe, поставить / обновить / удалить | S |

**Решения приняты** (раздел 10): путь A, до 4 игроков, подключение через Steam.

## 2. Диагноз «Unkown Error» (подтверждён)

**Как воспроизвёл** (тестовая копия игры на жёстких ссылках, сама установка не тронута):
- без отладчика: через ~4,5 с появляется окно «Unkown Error»;
- под отладчиком игра работает (отладочная куча Windows добавляет 16 байт после каждого блока, и
  чтение за концом не падает);
- под отладчиком с `_NO_DEBUG_HEAP=1` получено нарушение доступа:
  `EXC C0000005 at 00483A3D` (`rep movsd`), чтение `0x04C43000`, `esi=0x6C` → индекс 3.

**Механизм** (адреса exe; имена — из реимплементации xntrz/tmnt2):
- `COptionData::COptionData` `0x489920`: `m_nGamepadNum = CController::Max()`,
  `m_pGamepad = new[m_nGamepadNum × 0x24]`. `CController::Max()` = `PHYSICALCONTROLLER_MAX` = 1 (клавиатура) + джойстики; на этом ПК n = 1;
- `COptionData::Snapshot` `0x4897A0` копирует **6** записей (`cmp esi, 0xD8`) из `m_pGamepad`;
- `Restore` `0x489800` правильно ограничен `min(n, 6)`. Реимплементация исправила и Snapshot (`i < m_iGamepadNum`);
- `WinMain` `0x53B3D0`: `try { … } catch (...) { SetError(1) }` → строка ресурса №6 «Unkown Error».

**Почему «то работает, то нет» на разных ПК:** зависит от раскладки кучи и числа геймпадов
(с 5 и больше джойстиками n ≥ 6, и ошибки нет). DxWnd или dgVoodoo «лечат» её случайно, потому что меняют раскладку памяти.

**Исправление (этап 0):** хук `Snapshot`: при n < 6 подставляется временный массив из 6 записей, где
записи n…5 заполнены значениями по умолчанию (как в `CGamepadOptionData::Initialize` `0x483A90`).
Сохранение настроек не меняет формат, записи для отсутствующих геймпадов становятся
предсказуемыми вместо мусора из кучи.

## 5. Архитектура и выбор пути

**Путь A — ASI-мод к оригинальному `TMNT2.exe`** (как tmntnet для TMNT1).
Ultimate ASI Loader под именем `winmm.dll` (игра его импортирует) загружает `tmnt2net.asi`. Все
патчи делаются в памяти после проверки SHA-256 exe. Общий код с TMNT1 (лог, ini с комментариями,
транспорты ENet и Steam, протокол, join-коды, лобби, установщик) выносится в общую библиотеку.

**Путь B — своя сборка на исходниках xntrz/tmnt2.** Сеть, широкий экран и меню делаются прямо в коде.

| Критерий | A: мод к оригиналу | B: реимплементация |
|---|---|---|
| Точность игры | 100% оригинал | возможны расхождения и вылеты реимплементации |
| Сеть lockstep | нужен реверс тика, ввода и RNG (карта из B сильно сокращает работу) | проще: весь код открыт |
| 4 игрока | да (игра поддерживает 4) | да |
| Широкий экран | хуки RW + 2D-вызовов | правки в коде |
| Распространение | только наш код (мод + загрузчик) | бинарник содержит код RenderWare/CRI, публиковать нельзя |
| Сборка | MSVC x86 (уже есть) | + DirectX SDK June 2010, RW/CRI SDK из сторонних репозиториев |
| Совместимость с вашей русской сборкой | гарантирована (тот же exe) | надо проверять (ролики, голоса, шрифты) |

**Рекомендация: путь A**, а xntrz/tmnt2 использовать как справочник (имена, структуры, детерминизм).
Если на этапе 3 окажется, что оригинал недетерминирован и это не исправить (расхождение в
replay-тесте), переходим на путь B для сетевой части. Это решение принимаем по результату
replay-теста.

**Модель сети (этап 4): lockstep по вводу.** У каждого игрока своя копия игры. В кадре N каждая
сторона подаёт в игру ввод всех игроков за кадр N (с задержкой 2–4 кадра). Видео по сети не
передаётся, задержка картинки нулевая. Это возможно, потому что логика идёт фиксированным шагом
60 Гц (пропускается только отрисовка, `CPCFrameSkipController`), а случайные числа идут из одного
генератора RenderWare (`RpRandomSeed`/`RpRandom`), сид которого синхронизируется.

Запасной быстрый вариант: Remote P2 как в TMNT1 (ввод по нашей сети, картинка через Parsec,
Sunshine/Moonlight или Steam Remote Play). Он даётся этапом 2 почти бесплатно.

## 6. Этапы, состав работ и приёмка

### Этап 0. Запуск и режимы экрана — **сделан (tmnt2net 0.1.0)**
1. Фикс «Unkown Error» (раздел 2).
2. Все разрешения: снять фильтр 4:3/1024×768 (`0x5360A0: jmp` на проверку глубины). Меню игры ГРАФИКА
   покажет все режимы монитора, включая 16:9 и 21:9.
3. Режимы `[video] mode`:
   - `borderless` (по умолчанию) — окно без рамки на весь монитор, разрешение рабочего стола не меняется;
   - `windowed` — окно с рамкой, по желанию изменяемое (пропорции сохраняются), размер `window_size`;
   - `fullscreen` — эксклюзивный, как в оригинале, но в любом разрешении.
   Для `borderless/windowed` включается встроенный оконный режим игры (`[0x6E0158] = 1`), окно размещает мод
   (хук `+0x5C`), `GetClientRect` для окна игры сообщает размер кадра (RW не пересоздаёт буферы),
   D3D9 `CreateDevice` получает `SwapEffect = COPY`, `Present` вписывает кадр в окно с полями.
4. Картинка без растяжения до этапа 1: `aspect = 4:3` — кадр 4:3 (на 1920×1080 это 1440×1080) по
   центру с чёрными полями; `aspect = stretch` — растянуть на весь экран.
5. Alt+Enter: окно ↔ без рамки. Курсор скрыт над игрой в режиме без рамки.
6. `background = pause|run`: работать ли, когда окно не в фокусе (для сети и тестов — `run`).
7. Журнал `tmnt2net.log`: версия, хэш exe, какие патчи стоят, режим и размеры. Исключения в коде игры
   пишутся с модулем+смещением и регистрами, текст «Unkown Error» тоже попадает в лог.
8. `[debug] multi_instance = 1` — снимает проверку `FindWindowA` (нужно для тестов сети на одном ПК).
9. Установка: в папку игры кладутся `winmm.dll` (Ultimate ASI Loader), `tmnt2net.asi`, `tmnt2net.ini`.
   Чтобы удалить мод, достаточно удалить эти три файла.

Найдено и исправлено по ходу тестовых прогонов:

10. **Вылет, если окно не в фокусе во время загрузки** (Alt+Tab): игра захватывает клавиатуру сразу и при
    отказе выключает весь ввод, потом ASSERT `m_ppPhysicalController != NULL` → «Unknown error. Program is
    ended compulsorily». Патч `0x537611: jge → jmp` (`[fixes] keyboard_focus`).
11. **В окне игра рисовала в углу 640×480**: `ScreenWidth/Height` брали размер полноэкранного режима. Теперь
    в оконных режимах — размер кадра.
12. **`TMNT2.ini` после мода ломал бы оригинал**: игра при выходе записывает текущий размер, а оригинал
    стартует только с 4:3 до 1024×768. Мод даёт записать только такой размер.
13. **Закрытие окна (крестик, Alt+F4)**: в оригинале его нет. Выход во время ролика падал внутри ntdll
    («Unkown Error»), теперь игра закрывается без ошибки.
14. Внутренние ASSERT игры пишутся в лог с условием, файлом и строкой.

**Приёмка этапа 0 (результаты, копия `test-game2`, окно за краем экрана, без фокуса):**

| Проверка | Результат |
|---|---|
| Старт без геймпадов, без «Unkown Error» | да: `gamepad snapshot: n=1, padded to 6`, игра идёт 50 с (логотипы, вступительный ролик) |
| Окно / без рамки, разрешение рабочего стола не меняется | да: окно 960×720 и 1040×780; без рамки 1920×1080, кадр 1440×1080 с полями 240 px |
| Картинка на весь кадр | да (после п. 11), кадры из буфера D3D проверены |

### Этап 1. Широкий экран — **сделан (tmnt2net 0.2.0)**

Как сделано (адреса в re/notes.md §8):
- Hor+: `RwCameraSetViewWindow` расширяет окно обзора `(x, 0.75x)` у камер с кадром шире 4:3, на 5:4 растёт высота;
- 2D: виртуальный экран спрайтов (`CSprite::SetDefaultVirtualScreen`) и метрика Rt2d (`Rt2dDeviceSetMetric`,
  в розничном exe — константы) расширены так, что 640×480 виртуальных единиц занимают центр 4:3;
- сцены Rt2d Maestro (выбор героя, титульный экран, окна) — `CAnimation2D::Start` вписывает их в 4:3 и сдвигает в центр;
- ролики CRI — `CPCMovie::Draw` сужает полноэкранный спрайт до 4:3;
- затемнения, полосы окон и маркеры над героями (в реальных пикселях) остаются на всю ширину;
- темп: `timeBeginPeriod(1)` и точный ограничитель 60 в `Present` вместо ожидания игры 16 мс + Present (~57 кадров/с).

**Приёмка (кадры из буфера игры, тестовая копия):**

| Проверка | Результат |
|---|---|
| 16:9 1920×1080 | заставки, ролик (4:3 с полями), титульный экран, главное меню, выбор героя, «ВЫ УВЕРЕНЫ?», уровень, пауза — без растяжения |
| 21:9 1600×686 | уровень и пауза: обзор шире, HUD в центре 4:3 |
| 5:4 1000×800 | обзор выше, HUD и пауза в пропорциях |
| Сравнение с `aspect = 4:3` | расположение меню и HUD то же, что в 4:3 |
| Частота | 60,0 кадров/с (было 50–57) |
| Не проверено | враги у краёв широкого кадра (отсечение), режим `fullscreen`, смена разрешения из меню игры на ходу (2D останется по старым пропорциям до перезапуска) |

Исходный план этапа:
1. Hor+ для 3D: хук `RwCameraSetViewWindow` (`0x54AB50`), вертикальный FOV сохраняется, горизонтальный расширяется.
2. 2D: HUD, меню и надписи — в центре 4:3; затемнения и вспышки на всю ширину; ролики Sofdec 4:3 с
   полями (как вариант — размытые поля, как в TMNT1). Места вызова Im2D/Rt2d разбираю по одному: форк
   Key1aN показал, что общий «зажим в 4:3» ломает меню.
3. Проверить отсечение врагов и камер за краями 4:3 (в TMNT1 были проверки «за экраном» по 4:3).
4. `vsync`, ограничение кадров, мониторы 120/144 Гц без ускорения логики.
5. Настройки: `aspect = auto|4:3|stretch`, `hud = center|stretch`, `fov` (множитель).

### Этап 2. Управление — **сделан (tmnt2net 0.3.0)**

Как сделано (re/notes.md §9):
- игра читает джойстики DirectInput в раскладке адаптера PS2 и каждый кадр проверяет `GetDeviceStatus`;
- мод показывает игре **виртуальные джойстики** (свой COM-объект `IDirectInputDevice8A`) в этой раскладке:
  `EnumDevices`, `CreateDevice`, `GetDeviceStatus` перехвачены, игра ничего не замечает;
- источники: **SDL 2.32** (XInput — Xbox и всё, что им притворяется; HIDAPI — DualShock 4, DualSense,
  Switch Pro), кнопки по положению (нижняя = Крест = атака), курки — L2/R2, оба стика; 4 слота с горячим
  подключением; физические геймпады, которые читает SDL, скрыты из списка игры (VID/PID, у XInput — «IG_»);
  остальные DirectInput-устройства остаются у игры;
- `keyboard_players = 2`: левая и правая половины клавиатуры — два виртуальных геймпада, игре их клавиши не видны;
- переназначение кнопок — в меню игры (ОПЦИИ), оно работает и для виртуальных геймпадов;
- лимит: клавиатура + не больше 5 джойстиков (игра хранит настройки 6 устройств).

### Этап 3. Подготовка к сети — **сделан (tmnt2net 0.4.0)**

Главное: **у каждого игрока своя копия игры и свой экран.** Видео по сети не идёт, как в TMNT1, где
второй игрок смотрел картинку хоста. Каждая копия сама считает и рисует игру, по сети пойдёт только
ввод (lockstep, этап 4). Для этого игра должна от одного и того же ввода давать одно и то же. На этом
этапе это проверено на двух копиях.

Как сделано (re/notes.md §10, `[debug] determinism = 1`):
- кадр N закрепляется в `CPCInputsDevice::Sync`: все чтения DirectInput игры идут только там. В этот момент
  мод собирает **ввод кадра** (`FrameInput`): клавиатура, 4 геймпада (кнопки, стики, «подключён») и
  ответы на то, что логика спрашивает у реального времени. Весь кадр игра видит только его;
- найдено и закрыто, что зависело от скорости ПК:
  - пропуск отрисовки при отставании: эффекты при отрисовке берут случайные числа, поэтому пропуск выключен;
  - загрузка файлов (ADXF) и звука (поток звука) занимала разное число кадров, теперь она заканчивается
    внутри кадра;
  - **конец ролика** (Sofdec идёт по часам) и **«голос ещё звучит»** (от него зависит выбор следующей
    реплики, а с ним и `Rand`) — теперь это флаги во вводе кадра;
  - геймпады: в сетевом режиме у всех ровно 4 виртуальных геймпада, свои джойстики ПК игре не видны;
- `RpRandomSeed(123456)` вызывается до первого кадра и в начале демо-роликов титульного экрана, в сюжете
  генератор просто идёт дальше;
  время в логике — фиксированный шаг 1/60;
- инструменты: `frame_script` (клавиши в точные кадры), `record` / `replay` (запись ввода; повтор
  идёт следом за копией, которая ещё пишет), `rng_mutant_frame`, `tmnt2net-sim.log`: по строке на кадр
  (кадр, эпоха сида, число вызовов `RpRandom`, хэш генератора, хэш ввода).

**Камера — часть логики.** Активность врагов (видны ли они в кадре), прицеливание ИИ, предметы и общая
камера, которая отдаляется, чтобы все игроки были видны, считаются по матрице и пирамиде видимости камеры.
Поэтому:
- **отдельная камера у каждого игрока невозможна без рассинхрона**: в игре одна камера, которая держит в
  кадре всех игроков, как в локальном коопе. Каждый видит ту же сцену на своём мониторе;
- широкий экран (Hor+) меняет логику, поэтому в сессии у всех должно быть одно соотношение сторон и `fov`
  (берутся у хоста; монитор другой формы получает полосы). Это входит в этап 4.

### Этап 4. Сетевая игра — **сделан (tmnt2net 0.5.0)**, проверка на двух ПК через Steam — за вами

Как сделано (re/notes.md §11, `netplay.cpp`, протокол `common/protocol.h`):
- **lockstep, звезда вокруг хоста.** Каждый ПК в кадре N отправляет хосту свой ввод на кадр N+D
  (D — задержка ввода, по пингу 2..10 кадров). Хост, собрав ввод всех на кадр N, рассылает **пакет кадра**:
  4 геймпада и флаги. Каждый ПК подаёт его игре в `CPCInputsDevice::Sync`. Пакеты повторяются по 8 кадров
  в каждой посылке, поэтому потеря пакетов не страшна;
- флаги одинаковые у всех: ролик кончился, когда кончился у всех; «голос звучит» — по хосту;
- **сессия начинается с первого кадра игры**: игра ждёт на чёрном экране с лобби, поэтому у всех одно и то
  же начальное состояние. Клиенты получают сохранение хоста (`tmntsave-net.dat`, путь сохранения игры
  подменяется одним байтовым патчем), своё сохранение не трогается;
- проверка «та же игра»: отпечаток exe и файлов данных (размеры, `TMNTE.DAT`, 64 куска `TMNT.DAT`), иначе
  понятный отказ;
- в сессии у всех: кадр 16:9 с полосами, камера ровно 16:9, `fov` 1, работа в фоне, без эксклюзивного
  полного экрана;
- транспорт и Steam перенесены из tmntnet (TMNT1): ENet (LAN / IP, код `TMNT-XXXX-XXX`, порт 7790),
  Steam (ISteamNetworkingMessages + Steam Datagram Relay, лобби «tmnt2net» на 4 места, AppID 480,
  вход через «Присоединиться к игре»), мок Steam для проверок на одном ПК;
- на экране игры (текстура поверх кадра, видна в любом режиме): меню и лобби, «Ожидание: P2 …» при опоздании,
  кто подключился или отключился, «Рассинхронизация»;
- рассинхронизация: каждые 30 кадров клиенты шлют хэш генератора, хост сравнивает;
- отключение: игрок, который молчит дольше `timeout_ms`, выбывает с определённого кадра (его геймпад
  «отключён» у всех одновременно). Если вышел хост, у клиентов игра идёт дальше без сети. Войти в уже
  идущую игру нельзя: для этого нужен перенос состояния, которого у игры нет.

**Приёмка (одна короткая проверка на этом ПК, копии `test-game2` и `test-game3`, окна 640×360 за краем
экрана):**

| Проверка | Результат |
|---|---|
| Хост (ENet) и клиент по 127.0.0.1, `auto_start = 2` | клиент вошёл P2, получил сохранение хоста (пустое), старт вместе, задержка 2 кадра |
| Игра вдвоём: логотипы, титры, выбор героя (P1 и P2), ролик, уровень | **5 840 кадров совпали** на обеих копиях; у каждой свой экран: две черепахи, две панели P1/P2 |

| За вами | два ПК через Steam: вы и друг, у обоих эта же игра и мод |

Исходный план этапа:
1. Lockstep до 4 игроков; задержка ввода подбирается по пингу (2–4 кадра); отстающий → экран «ожидание
   игрока» с таймаутом, без зависания.
2. Подключение (решение: Steam): лобби, приглашения друзей, ретрансляция Valve, AppID 480 как в TMNT1.
   ENet (LAN/IP) остаётся внутренним транспортом для автотестов двух копий на одном ПК; показывать его
   игрокам — по желанию позже. Транспорты и протокол берутся из tmntnet.
3. Старт: хост выбирает режим и уровень; барьер перед уровнем; общий сид RNG, сложность и настройки хоста;
   проверка совпадения exe и данных (хэши `TMNT2.exe`, `TMNT.DAT`, …), при различии — понятный отказ.
   По итогам этапа 3:
   - ввод кадра (`FrameInput`) собирается со всех: геймпад каждого игрока идёт в его слот (P1–P4),
     клавиатура превращается в геймпад игрока;
   - флаги объединяются одинаково у всех: ролик кончился — когда кончился у всех (или кто-то пропустил его
     кнопкой), «голос звучит» — по хосту;
   - соотношение сторон и `fov` — хоста; у кого монитор другой формы — полосы;
   - lockstep начинается с одинакового состояния: все копии уходят на титульный экран с общим сидом
     (или стартуют вместе с запуска игры); сохранение хоста загружается у всех, своё сохранение клиента не
     перезаписывается.
4. Сохранения: прогресс у хоста; клиент может получить копию.
5. Разрыв: пауза и ожидание N секунд, затем игра без отвалившегося (его черепаха стоит или убирается) или
   выход в меню; переподключение по коду.
6. Десинк: лог с номером кадра, дамп состояния у обеих сторон; восстановление — перезапуск уровня с хоста.

**Приёмка:** два ПК через Steam: два уровня сюжета вдвоём без десинка, разрыв и переподключение. LAN на
двух копиях одного ПК. Chaos-тест (5% потерь, 100 мс, дубли). Мок-Steam: все сценарии.

### Этап 6. Установщик и выпуск — **сделан (tmnt2net 0.7.0)**

`tmnt2net-setup.exe` (`src/setup/setup.cpp`, всё внутри одного файла):
- находит игру: рядом с собой, по записи установщика игры в реестре (`Uninstall`, InstallLocation /
  `Inno Setup: App Path`, любая запись, где лежит `TMNT2.exe`), или папка выбирается вручную;
- проверяет SHA-256 `TMNT2.exe` и предупреждает, если exe другой (мод с ним ничего не включит);
- ставит `winmm.dll` (Ultimate ASI Loader; уже стоящий для другого мода используется как есть),
  `tmnt2net.asi`, `steam_api.dll` + `steam_appid.txt`, `tmnt2net.ini` (настройки, которые уже есть,
  остаются), README;
- чужие файлы с теми же именами откладывает в `tmnt2net-backup\`; файлы мода от ручной установки
  (прежний `tmnt2net.asi`, такие же байты) считает своими;
- `tmnt2net-install.txt` — список поставленного; «Удалить мод» удаляет ровно его, возвращает отложенное,
  стирает журналы и `tmntsave-net.dat`; своё сохранение игрока не трогает;
- не трогает игру, пока она запущена; при нехватке прав перезапускается с правами администратора;
- ключи для автоматической установки: `/install <папка>`, `/uninstall <папка>`, `/quiet`.

Проверено на копии папки: установка в чистую папку (прежний `tmnt2net.ini` отложен и возвращён при
удалении), обновление, установка поверх ручной (ничего не отложено, удаление оставляет только `TMNT2.exe`).

  матрица камеры; чей игрок — по геймпаду, который он занял на выборе героя). Проверено на двух копиях:
  «leonid» над P1, второй ник над P2, 4333 кадра совпали;

## 7. Настройки `tmnt2net.ini` (этап 0; дальше дополняется)

```ini
[video]
mode = borderless        ; borderless | windowed | fullscreen
resolution = auto        ; auto | 1920x1080 | game (из TMNT2.ini / меню игры)
aspect = 4:3             ; 4:3 (поля) | stretch;  на этапе 1 добавится hor+
window_size = auto       ; клиентская область окна, auto = 3/4 высоты рабочей области
window_resize = 1        ; окно можно тянуть (пропорции сохраняются)
vsync = -1               ; -1 как в игре, 0 выкл, 1 вкл
background = pause       ; pause | run (в фоне игра продолжает работать)
hide_cursor = 1          ; прятать курсор над игрой (без рамки / полный экран)

[fixes]
gamepad_snapshot = 1     ; фикс «Unkown Error»
keyboard_focus = 1       ; не падать, если при загрузке окно не в фокусе
all_modes = 1            ; все разрешения монитора в списке игры

[log]
level = info             ; error | warn | info | debug
exceptions = 1           ; исключения в коде игры -> лог

[debug]
multi_instance = 0       ; разрешить вторую копию игры (тесты сети)
```

## 8. Нефункциональные требования и правила

- `TMNT2.exe` на диске не меняется; патчи только в памяти и только при совпадении SHA-256. Если exe
  другой, игровые патчи выключаются, мод пишет в лог и не роняет игру.
- Всё x86, статический CRT (без VC++ redist). Файлы игры не попадают в репозиторий и релизы.
- В `DllMain` ничего тяжёлого: патчи ставятся в `InitializeASI` (до WinMain игры).
- Лог со временем и `fflush` после каждой строки.
- **Тесты:** ваша установка не трогается, только копии на жёстких ссылках. Полноэкранные запуски на
  вашем ПК запрещены: только `windowed`/`borderless` без смены разрешения, без захвата фокуса и
  только с вашего согласия. Скриншоты — своими средствами из кадра игры, не снимок рабочего стола.
- Каждый фикс подтверждается запуском «до/после». В отчётах прямо пишу, что проверено и как.

## 9. Риски

| Риск | Что делаем |
|---|---|
| Оригинал недетерминирован (float, время в логике) → десинк | replay-тест на этапе 3 до сетевой части; при провале — путь B для сети |
| Шифрованный код в `.ysnkvb` (8,5 тыс. ссылок из игры) мешает хукам | пока не проявился; хуки ставятся в местах без ссылок туда; проверяется на каждом этапе |
| HUD при Hor+: много отдельных 2D-систем | разбор по местам вызова, настройка `hud = stretch` как запасная |
| Русская сборка у второго игрока другая | проверка хэшей данных при подключении; в README — какая сборка нужна |
| RW в оконном режиме пересоздаёт буферы при смене размера окна | подмена `GetClientRect` для окна игры (решено так в TMNT1) |
| Реимплементация без лицензии | только как справочник; код в мод не копируется |

## 10. Решения (приняты 2026-11-16)

1. **Путь для сети: A** — мод к оригинальному `TMNT2.exe`; xntrz/tmnt2 — только справочник.
2. **Игроков по сети: до 4.**
3. **Подключение: Steam.**
4. **Тестовые прогоны:** разрешены защищённые прогоны тестовой копии: окно за краем экрана, без фокуса,
   без диалогов, автозакрытие; если оконный режим не включился за 2,5 с, процесс убивается до смены разрешения.
